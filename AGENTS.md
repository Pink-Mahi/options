# AI Options Income & Profit Calculator

## Stack
- Next.js 14 (App Router) + React 18 + TypeScript (strict, `noUncheckedIndexedAccess`)
- Tailwind CSS + shadcn-style primitives in `src/components/ui`
- Prisma + PostgreSQL (Docker dev instance on :5432)
- Recharts for payoff/price charts
- Vitest for the calculation engine

## Commands
- `pnpm dev` — Next.js dev server (port 3001; use `pnpm exec next dev -p <port>` if 3001 is taken)
- `pnpm build` — production build
- `pnpm typecheck` — `tsc --noEmit`
- `pnpm test` — Vitest (calculation engine unit tests)
- `pnpm db:push` — push Prisma schema to DB
- `pnpm db:generate` — regenerate Prisma client

## Environment
Copy `.env.example` to `.env.local` (and `.env` for Prisma). Required for live data:
- `MARKET_DATA_PROVIDER=tradier`
- `MARKET_DATA_API_KEY=<Tradier token>`
- `TRADIER_BASE_URL` (sandbox: `https://sandbox.tradier.com/v1`)
- `TRADIER_ENTITLEMENT=delayed|realtime`

Without a key, the app runs in **demo mode** with a deterministic mock provider (clearly bannered). No functionality is lost.

AI (Phase 5, not yet active): `AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL`.

## Architecture (per spec)
- `src/lib/types.ts` — canonical domain models (single source of truth)
- `src/lib/calculations/` — **deterministic** financial engine. Every number in the UI, scanners, and AI layer comes from here. Unit-tested.
- `src/features/market-data/` — provider abstraction (`provider.ts`), Tradier (`tradier.ts`), mock (`mock.ts`), TTL cache (`cache.ts`), service (`service.ts`). Provider responses are normalized into canonical models; provider field names never leak.
- `src/features/options/` — scanners (`scanner.ts`) filter & rank using the calc engine; `stock-data.ts` assembles server payloads.
- `src/features/ai/` — AI provider abstraction + tool contracts (Phase 5). Stub returns templated analysis from the calc engine.
- `src/lib/database/` — Prisma client + portfolio repository (single default user/portfolio; auth is Phase 9).

## Product principles (enforced)
1. Math before AI. 2. Goals before rankings. 3. Total return before premium alone.
4. Portfolio before isolated trades. 5. Liquidity before headline yield.
6. Historical context, not certainty. 7. No trade is a valid result.
8. Explain opportunity cost. 9. Separate realized/unrealized/potential income.
10. Every recommendation is auditable.

Earnings IV crush analysis (`src/features/options/earnings-analyzer.ts`): historical earnings reactions (avg/median/max up/max down move, up-move frequency), next earnings date with countdown, expected move (historical avg vs ATM IV), IV crush estimate, strategy implications by proximity to earnings. All three exposed as AI tools (`getNews`, `getEarningsAnalysis`, `getPeerComparison`). 3 new API routes, 3 new tabs (News & Sentiment, Earnings, Peers). 18 AI tools total.
- **Phase 12 (Watchlist & alerts)**: Watchlist model added to Prisma schema. Watchlist repository (`src/lib/database/watchlist-repo.ts`) with CRUD for watchlist entries (symbol, notes, target price/IV/yield) and alerts. Alert evaluation engine (`src/features/alerts/alert-evaluator.ts`) checks 9 rule types against live market data: price_above, price_below, iv_above, iv_below, yield_above, yield_below, earnings_within_days, delta_above, delta_below. `/watchlist` page with add/remove watchlist items, create/toggle/delete alerts, triggered alert banner. 2 new API routes (`/api/watchlist`, `/api/alerts`). Watchlist added to main navigation (8 nav items).
- **Phase 13 (Backtester accuracy)**: Daily mark-to-market equity curve — drawdown, Sharpe, Sortino, and Calmar now computed from daily returns (not per-cycle), catching intra-cycle drawdowns that long-DTE strategies previously hid. Real-data cycles settle on the actual contract expiration date (bug fix — was settling on `idx + tradingDaysPerCycle`). Optional Friday-expiration snapping for the BS path (`snapExpiration` config). Idle cash interest accrual (`cashInterestEnabled` config, default off). Transaction costs: per-contract commission, assignment fee, slippage (`commissionPerContract`, `assignmentFee`, `slippagePerShare` configs, all default 0). Optimizer route enables all of these by default; single-backtest route exposes them as optional body params. Optimizer cache key bumped v3→v4. 9 new backtester tests (388 total).
- **Phase 13.2 (Wheel-grade metrics)**: 12 new wheel-strategy diagnostics in `BacktestResult`: `returnOnCapitalDeployed` (annualized P/L ÷ time-weighted avg capital at risk), `capitalUtilization` (fraction of days with an open option), `monthlyIncomeStdDev`, `zeroIncomeMonths`, `worstCyclePnl`, `worstMonthPnl`, `costBasisHistory` (date + basis after each assignment/call-away/avg-down), `netCostBasisReduction` (call premium per share held), `daysUnderwater` (days holding shares below cost basis), `regimeBreakdown` (cycles/P/L/winRate per bull/bear/crisis/recovery). New "Wheel Health" card in backtest-view.tsx with cost-basis badges and regime breakdown table. Optimizer table gains Sortino and capital utilization columns. 8 new tests (396 total).
- **Phase 13.3 (Normalized optimizer scoring)**: Replaced the old unit-mixed composite score (`annReturn * 0.4 + premium / 10000 + cycles * 0.5 + winRate * 10`) with a percentile-rank-based scoring system. 8 metrics (annualized return, Sharpe, Sortino, Calmar, outperformance, income consistency, capital utilization, RoC) are each ranked across the candidate set and combined with goal-based weights (cash_flow / balanced / long_term_gains). Min-cycles filter (≥12) penalizes statistically noisy candidates. Deflated Sharpe Ratio applied to top 5 to detect overfitting — likely-overfit winners get 30% score penalty, inconclusive get 10%. UI shows "Robust" / "Likely overfit" / "Inconclusive" badges on the recommended strategy. Cache key bumped v4→v5. Scoring logic extracted to `src/app/api/backtest/optimize/scoring.ts` (Next.js route files can only export HTTP methods). 9 new scoring tests (405 total).
- **Phase 13.4 (Walk-forward OOS validation + stability)**: New `src/lib/quant/walk-forward-options.ts` module validates the top 5 optimizer candidates across 4 sequential time folds (70% train, 30% test). Reports per-fold IS/OOS return, Sharpe, max drawdown; aggregates mean train/test return, IS/OOS gap, OOS consistency (fraction of positive folds), annualized OOS return. Parameter stability scoring evaluates neighboring configs (delta ±0.05, adjacent DTE, buyback ±10pp) and computes a stability score (fraction of neighbors within 50% of candidate's return). Robustness score = 50% OOS return + 30% stability + 20% consistency. UI shows "Stable plateau" / "Isolated spike" badges, OOS return column, stability column, and expandable IS/OOS detail card on the recommended strategy. Optimizer re-sorts top 20 by robustness score. 20 new walk-forward-options tests (425 total).
- **Phase 13.5 (Wheel management rules)**: New `BacktestConfig` fields for real-world wheel management: `manageAtDte` (close early when DTE drops to threshold), `stopLossMultiple` (close when option cost reaches N× premium collected), `skipEarningsWindow` + `earningsDates` (skip opening positions near earnings), `minIvRank` + `ivRankSeries` (skip when IV rank is too low), `rollTestedPut` (config for put rolling), `strikeMode` (delta/pctOtm/premiumTarget). New `BacktestResult` counters: `rolledPutCount`, `stopLossCount`, `earningsSkippedCount`, `ivRankSkippedCount`, `managedEarlyCount`. All rules are opt-in (default off) for backward compatibility. Fixed `rollOnAssignment` to sell a replacement call after buying back the ITM call (keeps the wheel in the call phase). Implemented `rollTestedPut` — rolls a tested put (delta exceeds threshold) to a later expiration for a net credit. 14 new tests (449 total).
- **Phase 13.6 (Advanced volatility + early assignment)**: New `src/lib/quant/volatility.ts` module: Yang-Zhang OHLC volatility estimator (overnight + intraday, ~8× more efficient than close-to-close), Garman-Klass estimator, regime-aware calibrated VRP (low/normal/high/crisis vol regimes adjust the IV multiplier), early assignment probability model for deep-ITM puts. New `BacktestConfig` fields: `volEstimator` (closeToClose/yangZhang/garmanKlass), `calibratedVrp`, `simulateEarlyAssignment`, `earlyAssignmentThreshold`. New `BacktestResult` field: `earlyAssignmentCount`. All opt-in for backward compatibility. 28 new tests (467 total).
- **Phase 13.7 (Ratio wheel)**: New `RATIO_WHEEL` strategy that sells both puts and calls simultaneously each cycle at a configurable ratio (`putCallRatio`, e.g. 0.5 = 50/50). When shares are held, sells a covered call (primary) + cash-secured put (secondary) sized by the ratio. After put assignment, dynamically increases the call delta (`callDeltaAfterAssignment`) to be more aggressive about being called away — this recovers shares at a higher strike after the put lowered the cost basis. After call-away, resets the call delta and rebalances back to puts-only. New `BacktestConfig` fields: `putCallRatio`, `callDeltaAfterAssignment`, `putDeltaTarget`. New `BacktestResult` fields: `ratioPutContractsSold`, `ratioCallContractsSold`, `ratioDeltaAdjustments`, `ratioRebalances`. 5 new tests (472 total).
